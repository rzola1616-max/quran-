## 1. The Two Android Apps

| | App 1 — **Quran Learning Companion** (User App) | App 2 — **Quran Learning Admin** (Admin App) |
|---|---|---|
| Audience | Public: beginners, readers, tajweed learners, hifz learners, families | Internal: owner, content managers, teacher-reviewers, support |
| Login | **Never required** for core features | **Required** (role-based) |

> **Assumption to confirm:** the master plan describes one user app and a Worker backend only. The Admin App is added because the requested App Flow document covers "User and Admin experience". If "admin" should be a web panel instead, only Sections 4 (Admin requirements) and the Admin parts of the other documents change.

**Shared backend:** one Cloudflare Worker project (`quran-learning-api`) + R2 (packs) + D1 (metadata) + Pages (privacy/help). Gemini key lives **only** as a Worker secret.

---

## 2. Vision and Promise

> Learn, read, listen, revise, and practise the Quran in one respectful app—with optional translations, offline-first functionality, and clearly explained AI assistance.

**Core rule:** The Quran reader and installed learning content always come first. Online AI is an enhancement, never a dependency for reading.

## 3. Goals and Non-Goals

### Goals
1. Complete, verified, licensed Quran reader that works in airplane mode.
2. Structured learning: Qaida → Tajweed → Hifz, with local progress.
3. Licensed recitation audio with offline download packs.
4. Honest, confidence-aware AI: on-device recitation model (when validated) + Gemini-backed explanations through the Worker.
5. Admin tooling so that content packs, lessons, reports and app config can be managed safely without app re-releases.

### Non-Goals (v1)
- Social features, public leaderboards, ads targeted at anyone (especially children).
- Mandatory accounts or cloud sync for users.
- LLM-generated Quran text, translations, tafsir, hadith citations, or fatwas.
- Running speech models inside a Cloudflare Worker.
- Claiming the app replaces a qualified teacher.

## 7. Non-Functional Requirements

| Area | Requirement |
|---|---|
| Offline | Airplane-mode acceptance test passes for every feature labelled offline |
| Performance | Reader first paint from local DB < 1 s on mid-range device; no jank on scroll |
| Storage | Packs are optional; user sees size before download; safe on low storage |
| Security | No secrets in APK/AAB/BuildConfig/assets; HTTPS only; input validation; rate limiting; admin RBAC + audit |
| Privacy | No ads/tracking; mic only on demand; no audio stored/uploaded by default; clear data disclosure |
| Accessibility | TalkBack labels, scalable text, contrast mode, reduced motion, RTL/LTR correctness, visible focus |
| Reliability | Network/API/model failure never crashes or blocks the reader; failed downloads never leave half-installed packs |
| Compatibility | Minimum Android version and device tiers decided in Phase 0 (proposal: API 26+) |
| Localization | Urdu + English UI first; others later |

## 8. Content, Licensing and AI Policy Requirements

1. Quran text, ayah numbering, diacritics, waqf marks, page mappings come from **one verified, licensed source**; checksum-verified; immutable in-app.
2. Every pack records source, language, publisher/translator, version, licence, checksum, size, updated-at (`CONTENT_SOURCES.md` maintained).
3. If using Quran Foundation Content Sync, follow its current terms and sync workflow.
4. Audio only from licensed/approved Qaris; no redistribution without permission.
5. AI jobs are split: on-device recitation engine ≠ Gemini explainer. Gemini never acts as Quran source or sole judge of recitation.
6. Prompt-injection resistance: retrieved content is data, not instructions.
7. Complex/disputed religious questions are redirected to qualified scholarship.

## 9. Success Metrics (privacy-respecting)

- Crash-free sessions ≥ 99.5%.
- 100% of offline-labelled features pass airplane-mode test before release.
- Pack download success rate and checksum-failure rate (aggregate, from Worker/pack endpoints only).
- AI report rate per 1,000 assistant answers (aggregate) trending down.
- Teacher-review turnaround time (admin).
- Play Store rating and accessibility feedback.
- *No per-user tracking is required to measure any of the above.*

## 11. Risks

| Risk | Mitigation |
|---|---|
| Licence problems with text/audio/translation | Phase 0 sign-off; `CONTENT_SOURCES.md`; admin licence status gate before publishing |
| On-device model quality/licence unknown | Treat as experimental; teacher-reviewed evaluation; interface-based swap |
| Open Gemini proxy abuse | Strict schemas, rate limits, budgets, kill switch, attestation later |
| Fake/incorrect religious content | Grounded answers, "insufficient reference", report button, review queue |
| Admin compromise | RBAC, short-lived tokens, audit log, no user data held |
| AI Studio output is single-module/prototype quality | Inspect, refactor, keep logical package boundaries |
