# 02 — Technical Requirements Document (TRD)

**Project:** Quran Learning Companion (User App + Admin App + Cloudflare Worker)
**Version:** 1.0 (draft) · **Date:** 29 Oct 2026

---

## 1. System Overview

```text
┌─────────────────────────────┐      ┌─────────────────────────────┐
│ User App (Kotlin/Compose)   │      │ Admin App (Kotlin/Compose)  │
│ Offline-first, no login     │      │ Online, role-based login    │
│ Room · DataStore · Media3   │      │ Retrofit/Ktor · DataStore   │
│ WorkManager · local AI      │      │ Keystore-protected tokens   │
└──────────────┬──────────────┘      └──────────────┬──────────────┘
               │ HTTPS /v1/*                          │ HTTPS /v1/admin/*
               ▼                                      ▼
        ┌──────────────────────────────────────────────────┐
        │ Cloudflare Worker  (quran-learning-api, TypeScript)│
        │ validation · rate limit · RBAC · audit · adapters │
        └───────┬──────────┬──────────┬──────────┬─────────┘
                ▼          ▼          ▼          ▼
            Gemini API    R2 (packs)  D1 (meta)  Pages (privacy/help)
          (secret server-side)
```

Three independent deliverables (separate repos/modules):
1. `quran-learning-companion` — Android user app
2. `quran-learning-admin` — Android admin app
3. `quran-learning-api` — Cloudflare Worker

Rule: the Worker is **not** a GPU/speech host. Speech recognition runs on-device (or on a separately validated service later).

## 3. User App Architecture

### 3.1 Layers
- **UI:** Compose screens/components only. Never touch DB, Gemini, downloads directly.
- **Domain:** use cases (OpenSurah, ToggleBookmark, StartDownload, ScheduleRevision, StartRecitationSession…).
- **Data:** repositories over Room, pack manager, settings, Worker client.
- **AI:** interfaces + implementations (see 3.4).

### 3.2 Package layout (inside one module; keep boundaries logical)
```text
app/src/main/java/<package>/
  app/                 Application, MainActivity, NavHost
  core/designsystem/   Theme, colors, type, components
  core/network/        WorkerApiClient, DTOs, ConnectivityMonitor
  core/database/       Room DB, DAOs, migrations
  core/files/          PackManager, checksum, storage checks
  core/audio/          Media3 player, session, notification
  core/ai/             AI interfaces, ModelStatus, confidence rules
  data/quran/          Quran local sources + repositories
  data/translation/    Translation & word-by-word
  data/learning/       Lessons, quizzes, hifz, progress
  domain/              Models + use cases
  feature/home | quran | audio | learn | ai_teacher | assistant | hifz | progress | downloads | settings
```

### 3.3 Key interfaces
```kotlin
interface QuranRepository
interface TranslationRepository
interface AudioRepository
interface DownloadPackRepository
interface LearningAssistantRepository      // Worker-backed
interface WorkerApiClient                   // knows only the Worker base URL + typed routes
interface RecitationRecognitionEngine       // on-device model behind an interface
interface AyahAlignmentService
interface RecitationFeedbackPolicy          // confidence thresholds from evaluation data
interface OnlineAiAvailabilityProvider
interface ModelPackageRepository
```

### 3.4 AI components (separate responsibilities)
| Component | Job | Not allowed |
|---|---|---|
| Local recitation engine | Streaming recognition, alignment to canonical ayah, confidence | Rewriting Quran text |
| `RecitationFeedbackPolicy` | Show issue only above calibrated confidence; else ask to repeat | Hard-coded thresholds without measurement |
| Gemini via Worker | Explain approved translation, lesson Q&A, study plan, app help | Generate Quran text/translation/tafsir/hadith, judge recitation |
| Optional online recitation provider | Replaceable adapter, **disabled by default** | Sending audio without explicit consent |

`ModelStatus = NotInstalled | Downloading | Ready | Incompatible | Failed | UpdateAvailable`

Model prerequisites: licence allows distribution; verified Android artefacts + runtime (e.g., ONNX Runtime Mobile) and ABIs; tested on low/mid/high devices (RAM, latency, battery, heat); download only from checksum-verified source.

### 3.5 Offline-first rules
- Room is the source of truth. Network never overwrites/erases local data on failure.
- Content updates go through controlled sync with atomic swap (temp → verify → swap).
- Stable ayah ID `ayahId = surah*1000 + ayah` preserves bookmarks/progress across updates.
- Online-only features show status + retry; no endless spinners.
- Skeleton loaders only for network calls.

### 3.6 Downloads & packs
- Pack manifest: `packId, type, version, sizeBytes, sha256, licenseUrl, downloadUrl, minAppVersion`.
- WorkManager unique work per pack; retry with backoff; resume where server supports `Range`.
- Verify SHA-256 → unzip/import in transaction → mark `INSTALLED`; otherwise rollback and delete temp.
- Check free storage before start; large files stay in app-private storage; **no audio blobs in Room**.

### 3.7 Audio
Media3 `MediaSessionService`, foreground playback only on user action, audio focus handling, repeat/loop modes, speed control, no autoplay.

### 3.8 Security & privacy (client)
- No API keys/secrets in source, BuildConfig, `strings.xml`, assets, remote config, APK/AAB.
- Only the public Worker base URL is configured (per build variant).
- HTTPS only; `networkSecurityConfig` disallows cleartext (except debug if needed).
- Mic permission requested contextually; recording buffers in memory; not persisted/uploaded by default.
- Backup rules exclude model/audio caches; user export excludes voice.
- Release: R8/ProGuard, signing keys outside repo.

## 4. Admin App Architecture

### 4.1 Modules (logical packages)
```text
app/ · core/designsystem · core/network (AdminApiClient) · core/auth (TokenStore, SessionManager)
feature/login · dashboard · sources · packs · lessons_review · reports · config · audit · admins
```

### 4.2 Authentication & authorization (decision required)
- Admin signs in through a Worker-mediated flow (candidates: Cloudflare Access/OIDC, email OTP, or passkeys). **Decision pending.**
- Worker issues **short-lived access token** + refresh token; both stored encrypted with Android Keystore-backed keys.
- Roles: `owner`, `content_manager`, `teacher_reviewer`, `support`. Enforced **server-side** on every `/v1/admin/*` route; the app only hides UI.
- `FLAG_SECURE` on sensitive screens; session timeout; biometric re-unlock optional.
- No admin credentials, signing keys, or provider keys in the APK.

### 4.3 Capabilities
Online-first; caches last dashboard/list responses read-only; destructive actions (retire pack, kill switch, role change) need confirmation and write to audit log.

## 5. Cloudflare Worker (API Gateway)

### 5.1 Repository layout
```text
cloudflare-worker/
  src/index.ts
  src/routes/{health,config,assistant,packs,reports,admin/*}.ts
  src/services/{gemini,content-provider,audit}.ts
  src/validation/schemas.ts
  src/security/{rate-limit,auth,rbac}.ts
  wrangler.jsonc · package.json · tsconfig.json · .gitignore · README.md · .dev.vars.example
```

### 5.2 Public routes (User App)
| Method | Path | Purpose |
|---|---|---|
| GET | `/v1/health` | Non-sensitive status + API version |
| GET | `/v1/config` | Safe public config, feature flags, min app version |
| GET | `/v1/packs` | Published pack metadata (optional) |
| GET | `/v1/packs/:id/manifest` | Version, size, checksum, licence, download source |
| POST | `/v1/assistant/ask` | Constrained educational Q&A |
| POST | `/v1/assistant/explain-translation` | Explain an existing translation by content ID |
| POST | `/v1/assistant/study-plan` | General study plan from goals/schedule |
| POST | `/v1/reports` | User-submitted AI feedback report (explicit consent) |

### 5.3 Admin routes (Admin App) — all require token + role
`/v1/admin/session`, `/dashboard`, `/sources`, `/packs`, `/packs/:id/versions`, `/packs/:id/versions/:v/publish|rollback`, `/lessons/review`, `/reports`, `/config`, `/audit`, `/admins`, `/models`.

### 5.4 Hard rules
- Narrow typed routes only. **No** `/proxy?url=`, no arbitrary model names, no raw provider requests.
- Strict schemas, max body size, max input/output tokens, timeouts, per-route cost budgets.
- Server-generated `requestId` on every response.
- If no approved reference is available → `status: "insufficient_reference"`; never fabricate.
- Anonymous traffic: client device IDs are **not** authentication; add attestation/signed short-lived sessions before scaling expensive AI.
- Logging: requestId, status, latency, error category, aggregates. **Never** keys, raw audio, full questions, stable identifiers.
- CORS only for explicitly allowed web origins (not a security control).
- Secrets: `npx wrangler secret put GEMINI_API_KEY`; local `.dev.vars` is git-ignored.

### 5.5 Response contract (assistant)
```json
{
  "requestId": "server-generated-id",
  "status": "ok | insufficient_reference | rate_limited | error",
  "language": "ur | en",
  "answer": "...",
  "references": [{ "type": "translation_or_lesson", "sourceName": "...", "reference": "..." }],
  "isAiGeneratedExplanation": true,
  "confidence": "limited | moderate",
  "disclaimer": "This explanation supports learning and is not a substitute for qualified scholarship."
}
```
Error envelope: `{ "requestId", "status":"error", "code", "message" }` — user-safe messages only.

## 7. Testing Strategy

| Layer | Tests |
|---|---|
| Quran integrity | 114 surahs, per-surah ayah counts, no missing/duplicate IDs, checksum match, diacritics/RTL rendering checks |
| Unit | Repositories, use cases, feedback policy, pack manager, checksum |
| Instrumented | Room DAOs/migrations, download failure/resume, airplane-mode flows |
| UI | Navigation, onboarding skip, offline states, permission-denied, large font, dark mode, TalkBack |
| AI recitation | Evaluation corpus: correct, omitted, substituted, extra word, noise, fast/slow; measure FP/FN, latency, battery, heat, memory; teacher-reviewed |
| Worker | Valid request, invalid schema, oversize body, missing key, provider timeout, provider error, rate limit, RBAC denial, audit write |
| Security | Secret scan of APK/repo, open-proxy test, token expiry, role bypass attempts |

## 8. Performance & Resource Budgets (initial targets, to be measured)
- Cold start to Home < 2 s on mid-range device.
- Reader opens from local DB without network call.
- Memory/battery/heat measured for the AI engine per device tier before any "supported" claim.
- Worker request timeout and Gemini token caps configurable per route.

## 9. Observability
- Worker: structured logs without secrets, aggregate usage tables, alerts on error rate/billing.
- Apps: crash reporting only if privacy policy and Play data-safety form disclose it; no behavioural analytics on reader/practice data.

## 10. CI/CD
- Android: lint + unit tests + assemble on PR; signed release built on protected branch only.
- Worker: typecheck + tests on PR; `wrangler deploy` to staging automatically, production by manual approval.
- Secret scanning on every commit.
- Android publishing (Play Console) and Worker deployment (Wrangler) are **separate processes**.
